# Ассемблер и дизассемблер LX-GPU

Набор из трёх заголовков без внешних зависимостей (C++17):

| Файл | Что внутри |
|---|---|
| `tools/isa.h` | единственный источник правды об ISA: таблицы кодов, поля слова, карта операндов, `encode`/`decode` и **правила архитектуры** (`validate`) |
| `tools/asm.h` | ассемблер: текст → 32-битные слова микрокода |
| `tools/disasm.h` | дизассемблер: слово → текст, который ассемблер собирает обратно в то же слово |
| `tools/isa_selftest.cpp` | самопроверка всего перечисленного (`make isa-selftest`) |

Ассемблер отклоняет то, что отклоняет `validate()`, а дизассемблер печатает `.word` для всего, что `validate()` отклоняет. Поэтому они не могут разойтись.

## 1. Быстрый старт

Программа на ассемблере (`fill.asm`):

```asm
        .org 0x20                   ; программа загружается в ROM с адреса 0x20
start:  LDI   R1, #100              ; число проходов цикла
        MOV   LOOP_CNT, R1
        LDI   LOOP_TGT, #body       ; адрес начала тела цикла
        MOV   R2, #0x55
body:   L MOV DATA0, R2             ; L = аппаратный цикл: тело выполняется 100 раз
        FLUSH 0                     ; вытолкнуть последнее слово канала 0 в память
        HALT  0
```

Из C++:

```cpp
#include "asm.h"
#include "disasm.h"

uint16_t org = 0;
std::vector<uint32_t> words = asm_assemble_file("fill.asm", &org);
if (words.empty()) return 1;            // ошибка, сообщения уже напечатаны в stderr
for (size_t i = 0; i < words.size(); i++)
    printf("%04zX  %08X  %s\n", org + i, words[i], disasm32(words[i]));
```

Вывод:

```
0020  21020064  LDI R1, #0x0064
0021  01480040  MOV LOOP_CNT, R1
0022  214A0024  LDI LOOP_TGT, #0x0024
0023  61040055  MOV R2, #85
0024  81580080  L MOV DATA0, R2
0025  40006000  FLUSH 0
0026  40004000  HALT 0
```

Из командной строки (`tools/asm.cpp`): печатает слова в hex по одному на строку, при ошибке возвращает код 1.

## 2. Формат строки

```
[метка:] [L] МНЕМОНИКА[.УСЛОВИЕ][.L] операнды [модификаторы]   ; комментарий
```

- Комментарий начинается с `;`.
- Регистры, мнемоники и условия **не чувствительны к регистру** (`mov r0, data0`). Метки чувствительны.
- Метка это `[A-Za-z_][A-Za-z0-9_]*` и двоеточие. Можно несколько меток подряд (`a: b: NOP`) и метку на одной строке с командой. Метка не может совпадать с именем регистра или мнемоникой ALU.
- Бит цикла `L` можно писать префиксом (`L ADD R1, #1`) или суффиксом (`ADD.L R1, #1`, `ADD.NE.L R1, #1`). Оба варианта дают одно и то же слово.
- Условие это суффикс (`JMP.NE`, `MOV.EQ`), по умолчанию `AL` (всегда).
- Одна строка это одна команда, одна команда это одно 32-битное слово.

### Числа

Десятичные, `0x…` (hex), `0b…` (двоичные), со знаком `+`/`-`. Ведущий ноль **не** означает восьмеричную систему (`#010` это 10). Вместо числа в непосредственных значениях и в `.word` можно указать метку, это её адрес.

## 3. Операнды

### 3.1 Регистры общего назначения

`R0 … R31`: 16-битные, читаются и пишутся любой командой.

### 3.2 Специальные операнды

| Имя | Чтение | Запись | Примечание |
|---|---|---|---|
| `ZERO` | 0 | да (игнорируется) | приёмник «в никуда» |
| `FLAGS` | да | да | биты `[3:0] = V C N Z`; константа ≤ 15 |
| `BUSY` | да | нет | состояние кэша каналов |
| `SHADOW` | да | да | `[15:12]` флаги на момент `CALL`, `[11:0]` адрес возврата; запись пишет все 16 бит |
| `LOOP_CNT` | да | да | счётчик аппаратного цикла (16 бит) |
| `LOOP_TGT` | да | да | адрес начала цикла (12 бит, константа ≤ 4095) |
| `ROML`, `ROMH` | да | да | порт доступа к ROM (см. 3.3); чтение обращается к шине |
| `ROMA` | нет | да | адрес в ROM (12 бит) |
| `MHI` | да | нет | старшие 16 бит результата последнего `MUL` |
| `DATA0 … DATA3` | да | да | данные канала: чтение/запись пикселя или слова, обращение к шине |
| `IDX0 … IDX3` | нет | да | индекс пикселя канала |
| `IDXH0 … IDXH3` | нет | да | старшие биты индекса (3 бита, константа ≤ 7) |
| `STEP0 … STEP3` | нет | да | шаг автоинкремента индекса |
| `PAGE0 … PAGE3` | нет | да | `{mode[10:8], page[7:0]}` канала; константа ≤ `0x7FF` |

Коды 42 и 43 зарезервированы: ассемблер их не принимает. Операнды `RSV42`/`RSV43` существуют только в таблице имён.

### 3.3 Порт ROM

```
MOV ROMA, R1        ; адрес
MOV ROML, R2        ; защёлкнуть младшие 16 бит
MOV ROMH, R3        ; старшие 16 бит: слово записывается в ROM[ROMA], ROMA++
MOV R4, ROML        ; чтение младших 16 бит (ROMA не меняется)
MOV R5, ROMH        ; чтение старших 16 бит, ROMA++
```

Запись в слова ROM 0…31 (загрузчик) останавливает ядро с кодом `HALT 1`.

## 4. Команды

Все ALU-команды двухоперандные: `d = d op s`. Приёмник `d` это и первый операнд.

### 4.1 ALU

| Команда | Код | Действие |
|---|---|---|
| `MOV` | 0 | `d = s` |
| `MVN` | 1 | `d = ~s` |
| `AND` | 2 | `d &= s` |
| `BIC` | 3 | `d &= ~s` |
| `OR` | 4 | `d \|= s` |
| `ORN` | 5 | `d \|= ~s` |
| `XOR` | 6 | `d ^= s` |
| `XNOR` | 7 | `d = ~(d ^ s)` |
| `ADD` | 8 | `d += s` |
| `ADC` | 10 | `d += s + C` |
| `SUB` | 13 | `d -= s` |
| `SBC` | 15 | `d -= s + !C` |
| `ROR` | 16 | циклический сдвиг вправо на `s[3:0]` |
| `SHR` | 18 | логический сдвиг вправо на `s[3:0]` |
| `SAR` | 20 | арифметический сдвиг вправо на `s[3:0]` |
| `MUL` | 24 | знаковое 16×16: младшие 16 бит в `d`, старшие 16 в `MHI` |

Коды 9, 11, 12, 14 это те же `SUB`, `SBC`, `ADD`, `ADC` (RTL не смотрит на бит 2). Ассемблер всегда выдаёт коды из таблицы.

Источник `s` это регистр, специальный операнд или константа:

```asm
ADD  R1, R2           ; регистр
ADD  R1, #5           ; 11-битная константа
MOV  R3, DATA0        ; специальный операнд
```

### 4.2 Сравнение и проверка (псевдокоманды)

| Команда | Что собирается |
|---|---|
| `CMP a, b` | `SUB a, b` без записи результата, флаги обновляются |
| `TST a, b` | `AND a, b` без записи результата, флаги обновляются |

### 4.3 Загрузка константы

`LDI Rd, #значение`: 16-битная константа, диапазон −32768…65535. Может писать и в специальные операнды (`LDI LOOP_TGT, #body`, `LDI ROMA, #0x20`). Флаги не меняет.

### 4.4 Управление

| Команда | Действие |
|---|---|
| `JMP метка` или `JMP адрес` | переход (адрес 0…4095) |
| `JMP Rn` | переход по регистру. Подойдёт `R0…R31` и специальные операнды без обращения к шине (`SHADOW`, `LOOP_*`, `MHI`, …), но не `DATA*` и не `ROML/ROMH` |
| `CALL метка` | вызов: `SHADOW = {флаги, адрес следующей команды}`. `CALL` по регистру нет |
| `RET` | переход на `SHADOW[11:0]`, флаги не восстанавливаются |
| `HALT [код]` | остановка, код 0…127 (по умолчанию 0; 0 = успех) |
| `IRQ [код]` | прерывание хосту, код 0…255 |
| `FLUSH канал` | записать в память грязное слово канала и инвалидировать его; канал `0…3` или `CH0…CH3` |
| `NOP` | ничего |

Условие можно поставить на любую команду: `JMP.NE loop`, `MOV.EQ R1, #0`, `HALT.CS 3`.

### 4.5 Условия

| Суффикс | Смысл | Суффикс | Смысл |
|---|---|---|---|
| `AL` | всегда | `HI` | `C и не Z` |
| `EQ` | `Z` | `LS` | `не C или Z` |
| `NE` | `не Z` | `GE` | `N == V` |
| `CS` | `C` | `LT` | `N != V` |
| `CC` | `не C` | `GT` | `не Z и N == V` |
| `MI` | `N` | `LE` | `Z или N != V` |
| `PL` | `не N` | `VS` / `VC` | `V` / `не V` |

Команда с ложным условием ничего не меняет: ни регистры, ни флаги, ни порты.

## 5. Флаги и модификаторы

Флаги `Z`, `N`, `C`, `V` пишутся только если у команды стоит бит `F`, а условие истинно.

- **По умолчанию `F = 1` у всех ALU-команд, кроме `MOV` и `MVN`.**
- `Z` и `N` берутся из результата. `C` и `V` меняют **только** `ADD`, `ADC`, `SUB`, `SBC` (и `CMP`). Логика, сдвиги и `MUL` оставляют `C` и `V` как были: это нужно для многословной арифметики (`ADD` потом `ADC`).
- `C` это перенос (для вычитания «не заём»).

Модификаторы в конце строки:

| Модификатор | Действие |
|---|---|
| `!w` | не записывать результат (флаги всё равно по `F`) |
| `!f` | принудительно `F = 1` |
| `!nf` | принудительно `F = 0` |

```asm
SUB  R0, #1            ; F=1 по умолчанию: цикл по Z
ADD  R1, #4 !nf        ; прибавить без изменения флагов
MOV  R3, DATA0 !f      ; MOV по умолчанию без флагов; здесь Z/N по значению пикселя
MOV  ZERO, DATA0       ; прочитать пиксель и сдвинуть индекс, не сохраняя
```

**Хазарды флагов, `LOOP_*` и `SHADOW` ассемблер не проверяет**: защиту делает ядро (задержка на один такт, если следующая команда читает то, что предыдущая ещё пишет).

## 6. Аппаратный цикл (бит `L`)

Бит `L` на команде означает «в конце этого слова, если `LOOP_CNT > 1`, перейти на `LOOP_TGT` и уменьшить счётчик». При `LOOP_CNT = N` тело выполняется ровно `N` раз; после цикла `LOOP_CNT = 1`, поэтому перед следующим циклом его нужно задать снова.

```asm
        LDI  R1, #16
        MOV  LOOP_CNT, R1
        LDI  LOOP_TGT, #body
body:   ADD  R2, #1
        L MOV DATA0, R2         ; последнее слово тела; L проверяется даже при ложном условии
```

Правила:
- Взятый переход в том же слове имеет приоритет над `L`.
- `L` разрешён на `JMP`, `RET`, `HALT` и на обычных командах. `L JMP.EQ exit` выходит из цикла по условию.
- **`L` на `CALL` запрещён**: после `RET` цикл не повторяется, а заканчивается. Если нужен вызов в теле цикла, поставьте `L` на следующее слово.
- Каждая итерация стоит один лишний такт (пузырь после перехода). Для горячих циклов разверните тело на несколько записей, `L` оставьте на последней.

## 7. Директивы

| Директива | Действие |
|---|---|
| `.org N` | перейти на адрес `N` (0…4095), пропущенное место заполняется нулевыми словами; назад нельзя |
| `.word v1, v2, …` | сырые 32-битные слова (−2³¹…2³²−1), метки допустимы |

`asm_assemble_file` отрезает ведущую `.org`: возвращённые слова начинаются с этого адреса, а сам адрес попадает в `*out_org` (в том числе `0`). Если первой директивы `.org` нет, `*out_org` не меняется. `asm_assemble` возвращает слова вместе с ведущими нулями от `.org`.

Программа длиннее 4096 слов не принимается.

## 8. Что ассемблер проверяет и отклоняет

Все ошибки выводятся разом в формате `файл:строка: error: сообщение` с исходной строкой; при любой ошибке функции возвращают пустой вектор.

| Нарушение | Причина |
|---|---|
| спецоперанд как приёмник не в `MOV`/`LDI` (`ADD IDX0, #1`, `MVN IDX0, R1`) | первый операнд ALU читается из регистрового файла, у спецоперанда там мусор |
| запись в `BUSY`, `MHI`, 42/43 | операнд только для чтения или зарезервирован |
| чтение `ROMA`, `IDX*`, `IDXH*`, `STEP*`, `PAGE*` | операнд только для записи |
| два обращения к шине в одной команде: `MOV DATA1, DATA0`, `MOV DATA0, ROML`, `MOV ROMH, ROML` | ядро обслуживает одно устройство за команду; сначала переложите значение в регистр |
| `CALL Rn` | косвенного вызова в ядре нет |
| `JMP DATA0`, `JMP ROML` | цель перехода не может быть обращением к шине |
| `L CALL …` | см. раздел 6 |
| константа вне диапазона: `#2048` (11 бит: −1024…2047), `LDI #65536`, `HALT 128`, `IRQ 256`, `FLUSH 4` | поле не вмещает значение, молчаливого обрезания нет |
| константа в спецоперанд больше размера регистра: `MOV IDXH0, #8`, `LDI ROMA, #4096`, `MOV FLAGS, #16` | ядро обрезало бы значение |
| неопределённая или повторная метка, метка с именем регистра | |
| неверное число операндов, неизвестная мнемоника/регистр/условие/модификатор, пустой операнд, `.org` назад | |

Не проверяется: допустимость значения формата в `PAGE` (`mode` 3 бита, любое значение принимается), смысл побочных эффектов (инкремент `IDX`), попадание перехода в «данные».

## 9. Дизассемблер

`const char* disasm32(uint32_t w)` возвращает строку во внутреннем буфере (следующий вызов её перезаписывает).

Формат тот же, что принимает ассемблер:

```
L SUB R0, #2          ; цикл, F по умолчанию, поэтому модификатора нет
JMP.NE 0x003
JMP R1
MOV R3, DATA0 !f      ; F не по умолчанию: добавлен модификатор
CMP R1, R2            ; SUB !w с F=1 печатается как CMP (аналогично TST)
FLUSH 2
HALT 0
MOV R0, R0 !w         ; нулевое слово
.word 0x0000F123      ; слово, которое ассемблер породить не может
```

Слово печатается как `.word`, если оно не проходит `validate()` или в нём есть биты, которых текст не выражает (зарезервированные поля, коды-алиасы 9/11/12/14, нестандартные `WRITE`/`F` у `LDI` и управляющих слов, `SX` без бита 10 и т.п.). Поэтому для **любого** 32-битного слова `asm(disasm32(w)) == w`.

## 10. Программный интерфейс

```cpp
// asm.h
std::vector<uint32_t> asm_assemble_file(const char* path, uint16_t* out_org = nullptr);
std::vector<uint32_t> asm_assemble(const std::vector<std::string>& lines,
                                   const char* name = "<asm>");
bool asm_assemble_ex(const std::vector<std::string>& lines, const char* name,
                     AsmResult& res, FILE* err = stderr);   // err = nullptr: без сообщений
uint32_t asm_line(const std::string& raw, std::map<std::string,int>& labels,
                  int cur_pc, int* ok);                     // одна строка, для совместимости

// disasm.h
const char* disasm32(uint32_t w);

// isa.h (namespace isa)
Insn  decode(uint32_t w);
uint32_t encode(const Insn&);
bool  validate(const Insn&, std::string* why = nullptr);
```

`AsmResult` содержит `words`, `first_org` (−1, если ведущей `.org` нет) и `ok`.

Все ограничения (диапазоны констант, размер ROM, `CALL_BY_REG`) собраны в начале `isa.h`. При смене архитектуры правится только это место и таблицы кодов.

## 11. Самопроверка

```
make isa-selftest
```

Проверяет:
- эталонные слова из `rtl/bootloader.hex` (`MOV R0, DATA0` → `01000B00`, `SUB R0, #2` → `6180D002`, `JMP.NE 3` → `44001003`, …);
- около 60 строк, которые обязаны отклоняться, и около 40, которые обязаны собираться;
- метки, `.org`, `.word`, оба написания бита `L`;
- круговое преобразование `disasm` → `asm` на ~1,9 млн слов (случайные слова и случайные допустимые команды): расхождений должно быть 0.

Ожидаемый итог: `ALL CHECKS PASSED`.

## 12. Изменения по сравнению со старой версией

- Ошибки больше не пропускаются молча: сообщение с номером строки и пустой результат.
- `FLUSH` принимает **номер канала** 0…3 (раньше число-маска).
- `HALT` ≤ 127, `IRQ` ≤ 255.
- `CMP` и `TST` работают.
- Диапазон `#imm` в ALU-командах расширен до 2047 (`OR R1, #0x700`).
- Появились модификаторы `!w`, `!f`, `!nf`, суффикс `.L`, регистронезависимость, `0b…`.
- `L` на `CALL` отклоняется.
- `.org 0` сообщает `out_org = 0`.
